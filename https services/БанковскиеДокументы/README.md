# Банковские документы (GetBankDocuments)

HTTP-сервис объединяет в одну выборку платёжные поручения (входящие и исходящие) и платёжные ордера и возвращает по каждому документу шапку, а при `full=true` - **все реквизиты шапки и все табличные части построчно** в виде пар ключ-значение.

**HTTP-сервис:** `bankdocs`
**Метод:** `get`
**Функция в конфигураторе:** `GetBankDocuments`

Состав документов:

- `Документ.ПлатежноеПоручениеВходящее`
- `Документ.ПлатежноеПоручениеИсходящее`
- `Документ.ПлатежныйОрдерПоступлениеДенежныхСредств`
- `Документ.ПлатежныйОрдерСписаниеДенежныхСредств`

Ответ всегда имеет формат:

```json
{
  "data": [],
  "errors": []
}
```

## Endpoint

```http
GET /main/hs/bankdocs/get
```

## Параметры

Все параметры опциональны.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `from` | дата | Начало периода. Работает только вместе с `to`. Форматы: `dd.MM.yyyy`, `dd-MM-yyyy`, `yyyy-MM-dd`. |
| `to` | дата | Конец периода, включительно до конца дня. |
| `date` | дата | Один день. Применяется дополнительно к `from`/`to`. |
| `code` | строка | Подстрока в номере документа (`ПОДОБНО %code%`). |
| `summ` | число | Точное совпадение по `СуммаДокумента`. |
| `approved` | булево | Фильтр по признаку проведения. Истина: `1`, `true`, `yes`, `да`. |
| `org` | строка | Подстрока в организации. Пост-фильтр. |
| `type` | строка | Подстрока в имени типа документа, например `ПлатежноеПоручениеВходящее`. Пост-фильтр. |
| `full` | булево | Полный ответ: все реквизиты шапки и все табличные части. Ключ читается как `full`, `Full` и `FULL`. |

## Поля ответа

Шапка есть всегда:

| Поле | Описание |
|------|----------|
| `ТипДокумента` | Имя объекта метаданных, например `ПлатежноеПоручениеВходящее`. |
| `Номер` | Номер документа. |
| `ДатаДокумента` | Дата в формате `dd.MM.yyyy`. |
| `Дата` | То же значение, для совместимости с остальными модулями. |
| `Организация` | Представление организации, либо `Не указана`. |
| `СуммаДокумента` | Сумма документа, `0` если не заполнена. |
| `Комментарий` | Комментарий, либо пустая строка. |
| `Проведен` | Признак проведения. |
| `ПометкаУдаления` | Признак пометки на удаление. |

### Без `full`

| Поле | Описание |
|------|----------|
| `ТабличныеЧасти` | Сводка `{ "Есть": булево, "Количество": число }` - суммарное число строк по всем ТЧ документа. |

### С `full=true`

| Поле | Описание |
|------|----------|
| `Реквизиты` | Объект: все реквизиты шапки документа, ключ - имя реквизита из метаданных. |
| `ТабличныеЧасти` | Объект: ключ - имя ТЧ, значение - массив строк. Каждая строка содержит `НомерСтроки` и по паре ключ-значение на каждый реквизит ТЧ. |

Состав `Реквизиты` и `ТабличныеЧасти` **не фиксирован**: он читается из метаданных конкретного документа, поэтому у разных типов набор ключей разный.

### Приведение значений

Значения реквизитов приводятся к JSON-совместимым:

| Тип в 1С | В JSON |
|----------|--------|
| Строка, Число, Булево | как есть |
| Дата | строка `dd.MM.yyyy` |
| Ссылка на объект | строковое представление |
| Пустая ссылка, `NULL`, `Неопределено` | пустая строка |

## Примеры

```http
GET /main/hs/bankdocs/get
GET /main/hs/bankdocs/get?from=01.02.2025&to=28.02.2025
GET /main/hs/bankdocs/get?date=15.02.2025&full=true
GET /main/hs/bankdocs/get?type=ПлатежноеПоручениеВходящее&approved=true
GET /main/hs/bankdocs/get?org=Демо&summ=15000
GET /main/hs/bankdocs/get?code=00-000123&full=true
```

## Замечания

- Документ читается через `ПолучитьОбъект()`, то есть по одному обращению к базе на документ. На широких периодах без фильтров ответ может быть тяжёлым - сужайте период или используйте `type`.
- Если объект документа прочитать не удалось, строка всё равно попадает в `data` с пустыми `Реквизиты` / `ТабличныеЧасти`, а причина уходит в `errors`. HTTP-код остаётся **200**.
- Сортировка: дата по убыванию, затем номер по убыванию, сквозная по всем типам документов.
